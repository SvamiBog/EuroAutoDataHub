## Чек‑лист оценки площадки (4.1)

Заполняется до написания паука. Если ответ на юридический вопрос — «нельзя», площадка не подключается.

**Юридическое**
- [ ] Условия использования (ToS): запрещён ли автоматический сбор; есть ли официальный API или партнёрская программа.
- [ ] robots.txt: разрешены ли страницы выдачи и API, которые использует паук. Решение фиксируется здесь;
      технически — `SCRAPY_ROBOTSTXT_OBEY` (закрывает M6 из аудита).
- [ ] Персональные данные: паук не сохраняет имена и телефоны частных продавцов (только ID продавца площадки).
- [ ] Нагрузка: лимиты на IP (`SCRAPY_CONCURRENT_REQUESTS_PER_DOMAIN`, `SCRAPY_DOWNLOAD_DELAY`), пул прокси — только
      чтобы не создавать нагрузку с одного адреса, а не для обхода прямого запрета.

**Техническое**
- [ ] Источник данных: JSON/GraphQL API сайта, JSON в HTML (`__NEXT_DATA__`) или разбор HTML.
- [ ] Антибот‑защита: Cloudflare, Akamai, DataDome; как проявляется блокировка (403, 429, страница проверки).
- [ ] Число объявлений в выдаче (`totalCount`) — без него не посчитать полноту шарда.
- [ ] Лимит глубины выдачи (сколько страниц отдаёт сайт) и фильтры для дробления: марка, годы, цена, страна.
- [ ] Стабильный ID объявления; наличие VIN, пробега, года, цены с валютой, продавца.
- [ ] Объём: число объявлений по странам и сколько запросов нужно на ежедневный полный обход.

**Решение**: подключить (какой паук), подключить позже (что мешает) или не подключать (почему).

## otomoto.pl, autovit.ro, standvirtual.com (4.3)

Все три — платформа OLX Group с одним фронтендом и GraphQL API. Паук один (`spiders/otomoto.py`),
площадки отличаются адресом, страной, хэшем запроса и, возможно, ID категории.

| Пункт | Оценка |
|-------|--------|
| Данные | `GET /graphql?operationName=listingScreen&variables=…&extensions=…` (persisted query) — JSON с `totalCount` и объявлениями, 50 на странице |
| Шарды | Марка (`filter_enum_make`), при превышении `MAX_PAGES_PER_SHARD` — диапазоны лет (`filter_float_year:from/to`) |
| Поля | ID, цена и валюта, марка и модель (значения площадки), год, пробег, топливо, КПП, мощность, VIN (если указан), продавец, город |
| Блокировки | 403 при высокой частоте; обрабатываются паузой, повтором и прокси |
| Смена API | Новый хэш persisted query даёт ошибку GraphQL на каждом шарде: обход останавливается (`shard_failures`), в отчёте — критический алерт. Хэш задаётся без изменения кода: `SCRAPY_OTOMOTO_QUERY_HASH`, `SCRAPY_AUTOVIT_QUERY_HASH`, `SCRAPY_STANDVIRTUAL_QUERY_HASH` (актуальный — в запросах браузера к `/graphql` на странице выдачи) |
| Проверить | Лимит глубины выдачи; фильтры лет; для autovit и standvirtual — хэш, `category_id` (у otomoto «легковые» — 29) и справочник марок (сейчас общий с otomoto); robots.txt и ToS |

## AutoScout24 (4.4)

Один паук на 8 стран (`spiders/autoscout24.py`). Страны: `SCRAPY_AUTOSCOUT24_COUNTRIES` или `-a countries=DE,IT`.

| Пункт | Оценка |
|-------|--------|
| Данные | Страницы выдачи `/lst/<марка>?cy=<страна>&ustate=U&sort=price&page=N&size=20` — Next.js, объявления в `<script id="__NEXT_DATA__">`: `props.pageProps.listings`, `numberOfResults` |
| Лимит выдачи | Не больше 20 страниц по 20 объявлений (400 на запрос) |
| Шарды | Страна + марка; дробление по году первой регистрации (`fregfrom/fregto`) до одного года, затем по ценовым полосам (`pricefrom/priceto`, EUR), дальше — пополам |
| Проверка фильтров | Если на странице больше одного объявления чужой марки, страны, года или цены, фильтр площадкой не применён: страница неудачная, шард неполный |
| Снятие с публикации | Шард с границами цены применяется, только когда запуск завершён штатно и все шарды той же страны и марки полные: объявление с новой ценой могло перейти в соседний шард |
| Поля | ID (UUID), цена (EUR), марка и модель (slug из названия), версия, год первой регистрации, пробег, топливо, КПП, страна, город, индекс, ID продавца. VIN в выдаче нет |
| Проверить | Актуальность разметки и имён параметров; справочник марок (`data/autoscout24_makes.json`); robots.txt и ToS (автоматический сбор, вероятно, запрещён — нужна юридическая оценка); антибот‑защита и допустимая частота |

## mobile.de (4.5)

**Решение: не подключать парсингом.**

- Сильная антибот‑защита на страницах поиска. Обход требует headless‑браузера и резидентных прокси; это дорого
  и противоречит условиям использования площадки.
- У mobile.de есть Search API для партнёров (дилеров и сервисов) по договору. Если данные mobile.de нужны,
  правильный путь — договор и API, а не парсинг.
- Рынок Германии уже покрывает AutoScout24.

Вернуться к вопросу, если появится доступ к API: паук‑адаптер к API реализуется на том же базовом классе.

## Дубли между площадками (4.6)

Один автомобиль может быть выставлен на нескольких площадках. После каждого прогона ingestor ищет дубли среди
активных объявлений (`app/dedup.py`, таблица `listing_duplicate`). В предложение, цены витрины и справедливую
цену дубль входит один раз — как объявление, появившееся раньше. В карточке объявления в API видны остальные
объявления того же автомобиля.

| Метод | Правило |
|-------|---------|
| `vin` | Одинаковый VIN (17 символов, не заглушка) — на любой площадке, в том числе на той же |
| `attributes` | Разные площадки, одна страна, каноничная модель, год и топливо; пробег ±max(500 км, 1 %), цена ±5 %; пара однозначная |

Ограничения:
- **Фото не сравниваются.** Перцептивный хэш требует скачивания изображений.
- **Модели разных площадок пока не сопоставлены.** Справочник моделей строится по значениям площадки,
  поэтому «seria-3» otomoto и «3er» AutoScout24 — разные модели. Для сравнения моделей между
  площадками и совпадения по атрибутам нужны сопоставления в `model_alias` (следующий шаг).

## Проверка на живом сайте

```bash
make probe SPIDER=autovit MAKES=dacia                          # 2 страницы на шард, без Kafka
make probe SPIDER=autoscout24 MAKES=bmw ARGS="-a countries=DE" PAGES=1
```

Паук пишет сообщения в `probe_<паук>.jsonl` вместо Kafka. Отчёт `car_scrapers/probe.py` проверяет:
- есть полный шард с объявлениями;
- цена, марка, модель, год и пробег заполнены у 90 %+ объявлений;
- нет ошибок API и неприменённых фильтров.

При проблемах смотрите примеры объявлений в отчёте, сырые ответы (`SCRAPY_RAW_RESPONSES_DIR`) и лог паука.

## Как подключить новую площадку

1. Заполнить чек‑лист выше.
2. Паук — подкласс `ShardedSpider` (`spiders/base.py`). Нужно задать:
   - `SOURCE_NAME`, `COUNTRY_CODE`, `ITEMS_PER_PAGE`, справочник марок;
   - хуки `page_url`, `extract_page`, `build_item`;
   - при необходимости `split_shard` и `item_matches_shard`.

   Шарды, полнота, 403, прокси, события обхода и итоги — общие.
3. Фикстуры ответов площадки и контрактные тесты: сообщения проверяются схемой `libs/eadh_common/messages.py`.
   Новые фильтры шарда добавляются в `SHARD_FILTER_KEYS` и в `app/lifecycle.py:shard_scope`.
4. `make probe` на живом сайте, затем добавить паука в `CRAWL_SPIDERS`.
