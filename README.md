# EuroAutoDataHub

Ежедневный сбор объявлений о продаже подержанных автомобилей с европейских площадок,
история каждого объявления, рыночная аналитика, поиск аномалий и алерты.

Пауки: **otomoto.pl** (Польша) — в работе; **autovit.ro** (Румыния), **standvirtual.com** (Португалия) и
**AutoScout24** (8 стран) — готовы, включаются после проверки на живом сайте ([SOURCES.md](docs/SOURCES.md)).
План развития — в [роадмапе](docs/ROADMAP.md).

## Архитектура

```
scheduler ──► Scrapy (4 площадки) ──► Kafka ──► ingestor ──► PostgreSQL ──► FastAPI (/api/v1: аналитика, аномалии)
 (каждый день)   │  пул прокси      │ listing_observations      ▲     │
                 │                  │ crawl_events              │     └──► Metabase (дашборды)
                 └── run_id,        └ ingest_dlq (ошибки)       │
                     шарды              lifecycle, курсы ЕЦБ, отчёт о прогоне,
                                        дневные наблюдения, витрина сегментов,
                                        аномалии ──► Telegram (алерты, дайджест «ниже рынка»)
```

| Сервис | Путь | Назначение |
|--------|------|------------|
| `scheduler` | `services/scrapy_spiders/car_scrapers` | Ежедневно в `CRAWL_AT` запускает обходы |
| `scrapy_runner` | `services/scrapy_spiders/car_scrapers` | Пауки `otomoto`, `autovit`, `standvirtual` (GraphQL платформы OLX) и `autoscout24` для ручного запуска. Общий базовый класс `ShardedSpider`. Публикуют наблюдения объявлений и события обхода (`run_started`, `shard_finished`, `run_finished`). Могут ходить через пул прокси |
| `ingestor` | `services/data_processor` | Пишет наблюдения и события в БД батчами. Ведёт журнал изменений объявлений и снимает объявления с публикации только по полным обходам. Загружает курсы ЕЦБ, строит отчёт о прогоне, ищет аномалии и отправляет алерты |
| `api_service` | `services/api_service` | FastAPI: объявления, журнал изменений, статистика, аналитика в EUR, аномалии и подписки; миграции Alembic |
| `metabase` | `bi/metabase` | Дашборды «Рынок», «Сегмент», «Объявление», «Здоровье сбора», «Аномалии» (профиль `bi`, дашборды как код) |
| `eadh_common` | `libs/eadh_common` | Общая модель данных, контракт сообщений Kafka, настройки БД |

Главные правила данных:
- объявление определяется парой «площадка + ID на площадке»;
- обход делится на шарды (марка; большие марки — по диапазонам лет);
- объявление снимается с публикации, только если его не было в **двух подряд полных** обходах его шарда;
- объявление, которое снова появилось на сайте, возвращается в продажу с записью `relisted` в журнале;
- один автомобиль на нескольких площадках (тот же VIN или совпадение атрибутов) учитывается в аналитике один раз.

## Быстрый старт (Docker)

Нужны Docker с Compose v2, git и make; Python и uv нужны только для разработки и `make probe`.
- **Windows:** Docker Desktop с WSL 2. Команды выполняются в терминале Ubuntu (WSL), репозиторий клонируется
  в домашнюю папку WSL, а не на диск `C:`.
- **Память:** выделите Docker 4 ГБ. В простое стек с Metabase занимает около 1,5 ГБ; во время обхода и
  работы с дашбордами — больше.
- **Порты:** 5433 (PostgreSQL), 9094 (Kafka), 8000 (API), 3000 (Metabase).

```bash
cp .env.example .env          # задайте пароль PostgreSQL, при желании TELEGRAM_*
make dc-build
make dc-up                    # PostgreSQL, Kafka, миграции, ingestor, API, планировщик
make db-seed-makes            # справочник марок (необязательно: заполняется и по ходу приёма)
make run-oto MAKES=audi,bmw   # разовый обход выбранных марок (без MAKES — все марки)
```

- API: http://localhost:8000/docs
- Логи: `make logs-ingestor`, `make logs-scheduler`, `make logs-api`
- Отчёт о последнем прогоне: таблица `crawl_run`, поле `report`

## Аналитика

**Дашборды (Metabase).** Задайте `MB_ADMIN_*` в `.env` и выполните:

```bash
make bi-up          # Metabase на http://localhost:3000
make bi-provision   # подключение к БД, вопросы и дашборды (повторный запуск обновляет их)
```

**API** (`/api/v1/analytics`, ключ в заголовке `X-API-Key`, если заданы `API_KEYS`):

| Эндпоинт | Что возвращает |
|----------|----------------|
| `/price-trend` | Медиана и квартили цены (EUR) по дням, неделям или месяцам и странам. Фильтры: марка, модель, годы, пробег, топливо, КПП |
| `/segments`, `/segments/timeseries` | Витрина сегментов: предложение (активные, новые, снятые), цены, срок экспозиции |
| `/depreciation` | Цена по возрасту автомобиля |
| `/delisted` | Снятые за период: срок экспозиции, доля со снижением цены, медианная скидка |

Пример: медиана Toyota Corolla 2019–2021 с пробегом 50–100 тыс. км в PL и DE по неделям:
`/api/v1/analytics/price-trend?make=toyota&model=corolla&year_from=2019&year_to=2021&mileage_from=50000&mileage_to=100000&country=PL&country=DE`

Витрина пересчитывается после каждого прогона. Пересчёт за период: `make stats-backfill FROM=2026-09-01 TO=2026-09-30`.

## Аномалии и алерты

После каждого прогона ingestor проверяет данные и пишет находки в таблицу `anomaly`: что найдено,
насколько сильное отклонение и почему. Алерты уходят в Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`);
без Telegram они пишутся в лог.

| Класс | Что ищется | Когда сообщается |
|-------|------------|------------------|
| Здоровье сбора | Объём ниже медианы за 7 дней на 30 %+, неполные шарды, досрочная остановка, ошибки API (например, сменился хэш GraphQL‑запроса), всплеск 403, баны прокси, нет обходов 36 ч, обход завис | В отчёте о прогоне; «нет обходов» и «завис» — сразу |
| Качество данных | Цена‑заглушка или опечатка, год в будущем, нулевой пробег у старой машины, неправдоподобная мощность, неизвестная валюта; падение заполненности полей | Флаг у объявления: его цена не входит в аналитику |
| Цены | Цена на 25 %+ ниже или выше справедливой (сегмент: модель, год ±1, страна, топливо, КПП; поправка на пробег и год) | Сводка после прогона |
| Поведение | Перевыставление под новым ID (VIN или продавец + атрибуты), частые смены цены, уменьшение пробега | Сводка после прогона |
| Рынок | Медианная цена или предложение сегмента отклонились от скользящей медианы за 28 дней | Сводка после прогона |

**Дайджест «ниже рынка».** Подписка на фильтр — каждое утро после прогона приходит список новых
и подешевевших объявлений, которые дешевле справедливой цены на заданную долю:

```bash
curl -X POST localhost:8000/api/v1/subscriptions -H 'Content-Type: application/json' \
  -d '{"name": "Corolla PL", "filters": {"make": "toyota", "model": "corolla", "country": "PL"}, "min_discount": 0.15}'
```

| Эндпоинт | Что возвращает |
|----------|----------------|
| `/api/v1/anomalies` | Аномалии с фильтрами: класс, правило, статус, страна, марка, даты |
| `/api/v1/anomalies/summary` | Число аномалий по правилам и precision по ручной разметке |
| `/api/v1/anomalies/below-market` | Активные объявления дешевле справедливой цены |
| `PATCH /api/v1/anomalies/{id}` | Разметка: `confirmed` или `false_positive` |
| `/api/v1/subscriptions` | Подписки на дайджест (GET, POST, PATCH, DELETE) |
| `/api/v1/ads/{id}` | Карточка объявления: справедливая цена, флаги качества, открытые аномалии |

Оценка precision ценовых аномалий: выгрузить выборку, разметить колонку `label` (1 или 0), загрузить обратно.

```bash
docker compose exec ingestor python -m app.anomalies sample --rule price_below_market -n 100 --out /tmp/sample.csv
docker compose exec ingestor python -m app.anomalies labels /tmp/sample.csv
docker compose exec ingestor python -m app.anomalies precision
```

## Площадки

Какие пауки обходят площадки каждый день, задаёт `CRAWL_SPIDERS` в `.env`: `otomoto,autovit,standvirtual,autoscout24`.
Новую площадку сначала проверьте на живом сайте — без Kafka, по паре страниц на шард:

```bash
make probe SPIDER=autovit MAKES=dacia
make probe SPIDER=autoscout24 MAKES=bmw ARGS="-a countries=DE" PAGES=1
make run-spider SPIDER=autoscout24 MAKES=bmw,fiat ARGS="-a countries=DE,IT"   # разовый обход в Docker
```

Если площадка сменила хэш GraphQL‑запроса (критический алерт `api_errors` в отчёте), новый хэш задаётся
в `.env` без изменения кода: `SCRAPY_OTOMOTO_QUERY_HASH` и т. п. Оценки площадок и порядок подключения
новой — в [SOURCES.md](docs/SOURCES.md).

## Прокси

Чтобы не нагружать один IP и не получить бан, запросы паука можно распределить по пулу прокси.
В `.env` задайте `SCRAPY_PROXIES=http://user:pass@host1:port,http://user:pass@host2:port`.
Запись `direct` добавляет в ротацию собственный IP.

- **Лимиты на каждый прокси.** У каждого прокси свой download slot Scrapy, поэтому
  `SCRAPY_CONCURRENT_REQUESTS_PER_DOMAIN`, `SCRAPY_DOWNLOAD_DELAY` и AutoThrottle ограничивают нагрузку
  на каждый IP отдельно. Общая скорость растёт с числом прокси в пределах `SCRAPY_CONCURRENT_REQUESTS`.
- **Выбор прокси.** Запрос уходит через наименее загруженный доступный прокси. У каждого прокси
  свой User‑Agent.
- **Бан или ошибка соединения.** На ответ 403/429 или ошибку соединения запрос повторяется через
  другой прокси. После `SCRAPY_PROXY_BAN_THRESHOLD` таких случаев подряд прокси уходит на паузу
  `SCRAPY_PROXY_COOLDOWN`; каждая следующая пауза подряд вдвое длиннее.
- **Все прокси на паузе.** Срабатывает обычная защита паука: пауза обхода и остановка при
  устойчивой блокировке.
- **Отчёт.** Статистика по прокси попадает в отчёт о прогоне, при банах уходит алерт `proxy_bans`.
  Пароли в логах не показываются.

## Локальная разработка

Нужен [uv](https://docs.astral.sh/uv/). Python 3.11 он установит сам.

```bash
uv sync                          # зависимости всех сервисов + dev-инструменты
make test                        # тесты всех сервисов
make lint                        # минимальный линт
make e2e                         # сквозной сценарий на запущенном стеке (make dc-up)

# тесты на настоящем PostgreSQL (витрины, аналитика): создают и удаляют временные БД
TEST_DATABASE_URL=postgresql+asyncpg://postgres:пароль@localhost:5433/postgres make test

set -a; source .env; set +a      # переменные окружения для локальных запусков
make run-oto-local MAKES=audi    # паук с хоста (Kafka на localhost:9094)
make api-dev                     # API с автоперезагрузкой
```

`make e2e` прогоняет десять «дней» обхода против фейкового сайта (источник `e2e.test`) и проверяет:
- снятие объявления после двух полных обходов;
- что неполный обход ничего не меняет;
- возврат объявления в продажу;
- дробление марки по годам;
- дневные наблюдения и витрину сегментов;
- перевыставление по VIN и уменьшение пробега;
- флаг качества у цены‑заглушки;
- критический алерт в том же прогоне при неверном хэше запроса и при HTTP 400;
- обход через три прокси, один из которых забанен;
- AutoScout24 с двумя странами: дробление по годам и ценовым полосам, пропуски в ценовом шарде.

## Настройки

Полный список — в `.env.example`.

| Переменная | По умолчанию | Смысл |
|------------|--------------|-------|
| `CRAWL_AT`, `CRAWL_TZ` | 02:00, Europe/Warsaw | Время ежедневного обхода |
| `SCRAPY_CONCURRENT_REQUESTS_PER_DOMAIN` | 8 | Параллельных запросов с одного IP (с прокси — через каждый прокси) |
| `SCRAPY_CONSECUTIVE_403_LIMIT` / `SCRAPY_PAUSE_DURATION` / `SCRAPY_MAX_PAUSES` | 3 / 300 / 5 | Пауза после серии 403 и остановка при устойчивой блокировке |
| `SCRAPY_MAX_PAGES_PER_SHARD` | 500 | Если страниц больше, марка делится по годам |
| `SCRAPY_MIN_MAKE_COMPLETENESS` | 0.95 | Доля собранных от `totalCount`, чтобы шард считался полным |
| `DELIST_AFTER_MISSED_RUNS` | 2 | Сколько полных обходов подряд без объявления нужно для снятия |
| `MAX_DELIST_RATIO` | 0.3 | Предохранитель: не снимать, если «пропало» больше этой доли шарда |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | — | Отправка отчёта о прогоне в Telegram |
| `SCRAPY_PROXIES`, `SCRAPY_PROXY_FILE` | — | Пул прокси (см. «Прокси»); пусто — запросы напрямую |
| `SCRAPY_PROXY_BAN_THRESHOLD` / `SCRAPY_PROXY_COOLDOWN` | 2 / 600 | Банов подряд до паузы прокси и длина паузы, с |
| `SCRAPY_MAX_CONSECUTIVE_FAILED_SHARDS` | 5 | Остановить обход после стольких шардов подряд без первой страницы (смена API) |
| `CRAWL_SPIDERS` | otomoto | Пауки ежедневного обхода: otomoto, autovit, standvirtual, autoscout24 |
| `SCRAPY_AUTOSCOUT24_COUNTRIES` | все 8 | Страны AutoScout24: DE, AT, BE, ES, FR, IT, LU, NL |
| `SCRAPY_OTOMOTO_QUERY_HASH` и т. п. | — | Новый хэш GraphQL‑запроса площадки OLX без изменения кода |
| `HEALTH_VOLUME_DROP`, `HEALTH_MAX_RUN_GAP_H` | 0.3 / 36 | Алерт: объём ниже медианы за 7 дней на эту долю; нет обходов столько часов |
| `PRICE_MIN_DEVIATION`, `PRICE_Z_THRESHOLD` | 0.25 / 3 | Ценовая аномалия: отклонение от справедливой цены и robust z‑score |
| `API_KEYS` | — | Ключи доступа к `/api/v1` через запятую; пусто — доступ без ключа |
| `MB_ADMIN_EMAIL`, `MB_ADMIN_PASSWORD` | — | Администратор Metabase для `make bi-provision` |
